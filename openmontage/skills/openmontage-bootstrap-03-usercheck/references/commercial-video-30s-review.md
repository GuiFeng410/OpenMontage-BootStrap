# 15 秒及以上商品视频审查流程

本规则适用于商品宣传、电商商品展示、佩戴演示等视频，且视频时长大于或等于 **15** 秒。

它是 `openmontage-bootstrap-03-usercheck` 与 `openmontage-bootstrap-04-produce` 的商品片审查扩展，不替代原有的 03 -> 04 生产顺序。

## 0. 评审模式（P0 冻结）

说明：本节定义用户**默认看到多少细节**，不是另起一条生产管线。生产顺序仍是 03 简报 → 04 出片。

| 模式 | `review_mode` | 用户默认看到 |
|------|---------------|--------------|
| **普通（默认）** | `normal` | 方案确认 → 10–15s 试片 → 完整初稿 → AI 标出的问题片段 → 修改清单 → 最终稿 |
| **专业** | `pro` | 另加总览表、分批 3–4 beat、逐段审查卡、候选与抽帧细节 |

≥15s 时**交给用户选择**普通或专业，不强制专业。  
普通模式下：完整总览、逐 beat 卡、候选状态机、五点抽帧等仍作为**内部证据**生成与保存，但不默认甩给用户。  
流程中可提示：「需要更细的逐段审查，可切换专业模式。」

**强制回复协议适用：**

- **专业模式**、以及用户明确要求的商品实验分批：每批结束后必须使用第 5.1 节「固定回复协议」。
- **普通模式**：不强制本批段表；但试片关仍建议两点确认（试片是否过关 / 是否继续全长）。

## 0.1 画面构成比例（推荐目标 · 软约束）

简报字段：`motion_mix`（`1:1` / `1:2` / `0:1` / `2:1`）、`motion_mix_source`。

| 运镜:AI生成 | AI生成视频约占 | 说明 |
|-------------|---------------|------|
| **1:1** | ~50% | **推荐（普通默认）** |
| 1:2 | ~67% | 成本↑、物品/人物一致性风险↑ |
| 0:1 | ~100% | 强提示成本与一致性 |
| 2:1 | ~33% | （更省可选；可能有幻灯片感） |

- 初排表 3 / 开烧：按整片 **AI 模型生成总秒数** 大概符合即可（约 ±10%–15%）；beat 自由切分，不按段数硬凑。  
- 审查卡中用户要求某段「运镜→AI」或反向：**允许**，更新计划；**终稿不强制贴死**原比例。  
- 偏离时脚注或口头告知：相对推荐偏动态/偏运镜，及费用或一致性风险。  
- **禁止**把比例当成交付硬门槛。

## 1. 触发条件

同时满足以下条件时启用本流程：

```text
视频用途属于商品宣传或电商商品视频
并且 duration_seconds >= 15
```

如果用途不明确，先询问用户；不要仅根据时长猜测为商品视频。

本流程与 provider 无关，Remotion、Agnes 或其他已获用户确认的渠道都必须遵守同一套审查规则。

## 2. 核心分工

```text
原流程负责生产顺序；
普通模式：试片 + 初稿 + 问题片段；
专业模式：总览表 + 分批逐段卡 + 固定回复协议 + 修改清单；
修改清单负责用户确认后再执行。
```

这些内容是同一条生产链的不同视图，不得另起一套互相冲突的时间线或镜头计划。

## 3. 用户可见的状态

### 3.1 总览表状态（专业模式）

总览表只使用三个状态：

```text
待过目
需修改
可以
```

### 3.2 段级裁定三档（每批确认时使用）

对**每一个 beat**，用户裁定使用：

```text
合格
满意
不合格
```

映射建议：

| 段级裁定 | 总览状态建议 | 能否进入后续合成 |
|----------|--------------|------------------|
| 合格 | 可以 | 是 |
| 满意 | 可以 | 是（可记优化备注，默认不挡） |
| 不合格 | 需修改 | 否，须问题字母或自然语言 + 修改清单门 |

候选素材的内部日志可以继续记录 `pending`、`rejected`、`approved`、`satisfied` 等状态，但不在普通用户默认界面展示。

图片或视频的详细质量结论放在逐段审查卡中，例如：

```text
图片结论：不合格 / 合格可用 / 满意
视频结论：需修改 / 可以
```

## 4. 总览表

**专业模式**首次展示完整视频计划时，只提供以下六个字段：

| 段落 | 时间 | 方式 | 角度/用途 | 当前素材 | 状态 |
|---|---:|---|---|---|---|
| beat_01 | 00:00-00:05 | 图片缩放（Remotion） | 正面开场 | 图片 1、2 | 待过目 |
| beat_02 | 00:05-00:11 | 图片运镜（Remotion） | 右前 45 度 | 图片 3 | 待过目 |
| beat_03 | 00:11-00:15 | 视频生成（Agnes） | 商品细节特写 | 视频候选 1 | 待过目 |

方式使用简单说明：

- `图片缩放（Remotion）`
- `图片运镜（Remotion）`
- `图片转场（Remotion）`
- `图片补充（Agnes）`
- `视频生成（Agnes）`

总览表下方只保留必要脚注：

```text
1. 图片和视频路径详见对应逐段审查卡。
2. “需修改”表示存在明确问题，等待修改清单确认。
3. “可以”表示用户已确认，可进入后续合成。
4. 不合格候选不进入正式时间线，但保留候选记录。
```

总览表使用累计时间码，避免只写片段时长造成定位困难。

**普通模式**：不强制展示本总览；改为试片确认卡 + 初稿问题列表。

## 5. 分批审核

**专业模式**：不要一次性展开 30-60 秒视频的全部逐段内容。

执行顺序：

1. 先展示完整总览表，不要求用户立即逐段评价。
2. 按 3-4 个 beat，或一个完整内容小段，生成当前批次的审查材料（审查卡）。
3. **本批收尾（固定回复协议，见 5.1）**：审查卡之后必须给出本批段表、两点必答、下一步费用动作、问题选项与填写示例；等用户明确回复后，才进入修改清单或下一批。
4. 所有批次确认后，才进行整片最终合成和最终观看。

每批建议控制在约 12-20 秒。开场、主体展示、细节展示、收尾可以作为自然分组。

**普通模式**：跳过强制分批；AI 预审后只展开问题片段。

### 5.1 每批结束后的固定回复协议（强制）

展示本批审查卡之后，Agent **必须**按下列结构收尾（缺一不可），然后停止等待用户。确认前禁止静默进入下一批，也禁止静默付费生成。

#### （1）本批段表

| 第N批段落 | 时间段 | 是否 合格/满意/不合格 |
|-----------|--------|------------------------|
| 审查卡 beat_01 | 0–4s | （待用户填写） |
| 审查卡 beat_02 | 4–9s | （待用户填写） |
| 审查卡 beat_03 | 9–14s | （待用户填写） |

#### （2）您需要回复我 2 点

```text
问题1：本批各段是否合格？（可用上表：合格 / 满意 / 不合格）
问题2：是否继续进入下一批，或有其它计划？
```

#### （3）若继续，下一步动作必须写清（含费用）

必须写清：将生成哪个 beat、渠道/方式、约时长、预估费用、将交付什么审查材料。例如：

```text
若第2点选择继续：开始生成 beat_04（Agnes，约 5s，预估再约 ¥0.18），
并做出 00:14–00:31 审查卡给你过目。
```

实验 API 预算须标明「非售价」。

#### （4）脚注 · 回复示例 · 问题选项

**合格/继续示例：**

```text
第一批通过。继续第2批。
01满意，02合格，03合格。继续第2批。
```

**不合格填写示例（不合格时必须展示，不可省略）：**

```text
02不行，问题：H。具体：运镜太像单纯放大。先改02再进第2批。
01满意，02不合格，问题：E、K。位置：约00:05-00:07。03合格。先改02。
第一批：01合格，02满意，03不合格，问题：I。转场突兀，先改03与02衔接。
```

也可用自然语言描述，不强制字母。

**问题选项：**

```text
图片问题：
A. 商品和参考图不像
B. 图片角度不符合计划
C. 商品形状、圆环或厚度变形
D. 颜色、材质或纹理变化明显

视频问题：
E. 视频抖动
F. 画面闪烁或亮度突然变化
G. 商品断裂、拉伸或局部消失
H. 运镜太单调，像单纯放大缩小
I. 转场突兀
J. 片段节奏太慢或太快
K. 前后片段衔接不自然
L. 黑帧、掉帧或导出问题
M. 其他问题
```

## 6. 逐段审查卡

每个 beat 的审查卡至少包括以下内容：

```text
段落：beat_09
时间：00:32-00:36
角度：重点动态展示
方式：视频生成（Agnes）
当前版本：candidate_01
当前状态：待过目 / 需修改 / 可以（总览用语）
段级裁定：合格 / 满意 / 不合格（用户填写）
```

### 视频预览

客户端可以直接展示时，提供预览；不能直接展示时，提供绝对路径：

```text
视频路径：F:/.../beat_09_candidate_01.mp4
```

### 参考图片和抽帧

参考图片要注明计划角度和用途。视频片段至少提供：

- 首帧；
- 中间帧；
- 尾帧；
- 问题时间点附近的帧。

转场问题还要补充前一段末尾和后一段开头的少量帧。

内部抽帧建议至少首、25%、50%、75%、尾；用户默认展示首/中/尾，有异常再展开。

### 图片审核

图片审核重点记录：

| 检查项 | 结论 | 说明 |
|---|---|---|
| 商品身份 | 通过/不通过 | 是否仍是同一件商品 |
| 计划角度 | 符合/不符合 | 是否满足该 beat 的角度要求 |
| 几何形态 | 稳定/变形 | 圆环、厚度、边缘是否异常 |
| 颜色材质 | 稳定/变化 | 是否仍符合身份 Manifest |
| 画面质量 | 可用/需替换 | 构图、清晰度和背景 |

### AI 初审

AI 只列出重点问题，并提醒用户自行观看：

```text
AI 初审：
- 商品颜色基本稳定；
- 暂未发现明显断裂；
- 00:32.00-00:33.00 有轻微抖动；
- 开头与上一段衔接略突兀；
- 动态仍偏向缓慢推近。

以上为 AI 初步判断，建议用户观看完整片段并自行确认。
```

## 7. 用户评判提示

每批审查材料中，除第 5.1 节固定协议外，可再附一条定位示例：

```text
示例：

beat_09，不合格。
问题：E、K。
具体位置：00:32.00-00:33.00。
处理意见：保留当前参考图片，先裁掉视频开头不稳定部分，
重新处理与 beat_08 的衔接。
```

用户也可以直接用自然语言描述，不强制使用编号。

## 8. 问题选项

与第 5.1 节相同，全文统一使用 A–M。推荐回复格式：

```text
beat_编号 + 问题字母 + 具体位置 + 修改意见
```

用户不知道如何归类时，直接描述现象即可。

## 9. 修改范围

默认只修改被指出问题的 beat，并附带前后各约 1 秒用于检查衔接。

```text
单段问题 -> 修改单个 beat
衔接问题 -> 修改相邻两个 beat
节奏或结构问题 -> 修改整组 beat
```

只有在时间重新分配、多个片段共同漂移、或整组节奏需要调整时，才重构多个 beat。

## 10. 修改清单确认门

用户反馈后（尤其存在「不合格」时），AI 必须先汇总修改清单，不得立即执行：

| 段落 | 用户指出的问题 | 修改方式 | 是否重做素材 |
|---|---|---|---|
| beat_09 | 开头抖动、衔接突兀 | 裁剪并重新处理转场 | 否 |
| beat_05 | 运镜单调 | 增加横向推轨和速度变化 | 否 |
| beat_11 | 商品局部变形 | 重新生成候选视频 | 是 |

然后要求用户选择：

```text
1 = 同意按照清单执行
2 = 需要调整修改方案
3 = 暂不修改，继续查看下一批
```

只有用户回复 `1` 后，才执行本批次修改。

## 11. 候选和回退规则

- 图片候选必须先经过图片审查，再进入对应 beat。
- Agnes I2V 只生成关键动态片段。
- **候选策略（与 P0 冻结一致）：**
  - 默认 `adaptive`：每关键 beat **1** 个候选 → 初审 → 不合格才条件重试；
  - 可选 `stable_dual`：关键 beat 直接 2 个候选（须简报显式开启）。
- 每个计划内 AI 视频 beat：在 `adaptive` 下合计约 **2** 次付费尝试（初试 + 条件重试）为默认上限；`stable_dual` 按双候选计。
- AI 初审不能替代用户确认。
- 用户裁定为「不合格」的候选不进入正式时间线。
- **禁止**在未达最大尝试次数前，因失败就静默把该 AI 段整段改成 Remotion 运镜。
- **重试用尽后**仍失败/不合格：停止静默回退，向用户说明可能原因（例如：模型生成请求多次失败，可能是网络不稳定、余额不足、服务限流或一致性未过），并给出选项：
  1. 用 Remotion 运镜顶替本段（会偏离推荐比例，须用户知情）
  2. 增加实验预算后再试 1 次
  3. 换参考图 / 调整提示词后重试
  4. 暂停，人工处理
- 重新生成前，必须保留原候选编号和用户问题记录。
- 任何付费或云端生成，仍须先说明 provider、模型、用途、候选数量和费用，再执行。
- **单笔计划费用**：若某一 beat 预计费用 **≥ ¥5**（不论累计），向用户**提示即可**，不因此强制停烧；触实验预算上限仍走费用闸。

## 12. 与 03 -> 04 主链的关系

```text
03-usercheck：确认主题、档位、时长、motion_mix、video_plan，并判断是否触发本规则（≥15s）。
本规则：规定商品视频的总览、分批审查、固定回复协议、修改确认、比例软约束和回退方式。
04-produce：按照已经锁定的计划生产，不自行改换 provider、模型；审查改 beat 方式后更新计划，允许终稿偏离推荐比例。
```

若用户改变视频时长、商品片目标、档位或 provider，回到 03 重新确认；不得在 04 内静默改变生产方向。
